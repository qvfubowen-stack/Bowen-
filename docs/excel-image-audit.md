## 六、之前「图片为空」的结论为什么产生

### 6.1 直接原因：只读了单元格的值

我的 XLSX 读取器（`tools/xlsx-reader.mjs`）读取的是 `<sheetData>` 里的
`<c>` 单元格及其 `<v>` 值。而这份工作簿的「图片」列（B 列 / H 列 / A 列）
**在单元格层面确实是空的**：

```
综合产品信息表 R4: A4="1"  B4=null  C4="056121113D..."  D4="普桑..."  E4="3001"  F4="D1=54mm..."
                            ↑
                      B4 真的是 null —— 但 B4 位置上方浮着一张图片
```

图片不是单元格的值，而是**独立于单元格的浮动绘图对象**，
存放在工作表之外的三层结构里：

```
xl/worksheets/sheet1.xml           ← 只有单元格数据，看不到图
xl/worksheets/_rels/sheet1.xml.rels ← 指向 drawing1.xml（这一层我没读）
xl/drawings/drawing1.xml            ← 图片锚点：from row/col（这一层我没读）
xl/drawings/_rels/drawing1.xml.rels ← rId → ../media/imageN.jpeg（这一层我没读）
xl/media/image1.png ... image681.jpeg ← 真正的图片二进制（这一层我没读）
```

我用 Excel 的 `cell.value` 口径去判断「有没有图片」，
这在 OOXML 里是**结构性地看不到**——不管用 pandas 还是 openpyxl，
只读 `cell.value` 都一样看不到，必须读 `worksheet._images` / 绘图层。

### 6.2 为什么当时没有察觉

| 环节 | 当时做了什么 | 为什么漏掉 |
|---|---|---|
| 结构侦察 | dump 了每张工作表的单元格矩阵 | dump 只输出单元格值，图片不在其中 |
| 列语义分析 | 识别出「图片」列存在且全空 | 由此**推断**没有图片，而不是去验证绘图层 |
| 报表 | 写「图片列为空 → 无产品图片」 | 把「读不到」当成了「不存在」 |
| 网站占位 | 显示 "Photo pending" | 基于上述错误结论 |

**根本教训**：「字段读不到」≠「数据不存在」。
判断 OOXML 里有没有图片，必须检查 `xl/media/`、`xl/drawings/`，
不能只看单元格值。这一条已写入本报告与验收测试（TEST B）。

### 6.3 顺带修掉的两个真实缺陷

做这次专项审计时，暴露并修掉了两个隐藏的解析缺陷：

1. **`.rels` 路径规则写错**
   我原先用 `path.replace(/^xl\//, 'xl/_rels/')`，
   把 `xl/worksheets/sheet1.xml` 变成了 `xl/_rels/worksheets/sheet1.xml.rels`（错）。
   正确规则是 `<dir>/_rels/<name>.rels`。
   这个错误同样存在于 `tools/xlsx-reader.mjs` 的注释解析里（所以批注一直读不到），已一并修正。

2. **OPC 相对路径的基准搞错**
   关系里的 `Target="../drawings/drawing17.xml"` 是相对于
   **拥有该关系的部件**（`xl/worksheets/sheet17.xml`）的目录，
   不是相对于 `.rels` 文件。按错基准会解析成
   `xl/worksheets/drawings/drawing17.xml`（不存在），导致读到的 drawing 内容为空、
   锚点数为 0。修正后一次解析出全部 798 个锚点。

## 七、映射方法与判定规则

### 7.1 建立映射的链路

```
图片二进制 (xl/media/imageN.ext)
   ↑ r:embed
绘图锚点 (xl/drawings/drawingN.xml 的 <xdr:oneCellAnchor>)
   │  from row / from col（OOXML 里是 0 基，+1 即 Excel 行列）
   ↓ 所在列决定属于哪个记录区块
记录行 (worksheet 的该行)
   ↓ 该区块的「博文编号」单元格
Bowen No. → 数据库 product_id
```

### 7.2 三级判定（绝不猜）

| 状态 | 判定条件 |
|---|---|
| **exact** | 锚点行**就是**该记录区块的产品记录行，且该行 Bowen 单元格能读出合法编号，且该编号在数据库里存在对应产品 |
| **review_required** | 能确定「属于哪一行」，但不能确定「属于哪个产品」：① 锚点行是记录行但 Bowen 读不出；② 锚点行是记录行但没填 Bowen；③ 读到了编号但数据库无此产品 |
| **unresolved** | 无法确定锚点属于哪条记录：列不在任何记录区块内 / 该表没有产品表结构 / 锚点没有位置信息 |

**关键取舍**：即使图片明显贴在某个产品旁边（例如工作表2 的两张图），
只要该表没有产品表结构，就标 `unresolved` 并保留原图，**不猜它是哪个产品**。

**外链占位**：drawing 里 `r:link="rId2"` 指向 `Target="NULL" TargetMode="External"`，
这是 WPS 留下的外部链接占位，**不是包内图片**。程序只认 `r:embed`，
所以这 0 条外部引用没有被误当成图片导出。
